## A1 – edge-to-edge insets under targetSdk 36 (API 35/36)

**Bug:** `targetSdk = 36` (`app/build.gradle.kts:14`) makes Android 15+ draw the app under the status bar, cutout and
navigation bar; `android:statusBarColor`/`navigationBarColor` in `res/values/themes.xml:3-4` are ignored there.
Nothing in `app/src/main` handles window insets. On API 35/36 the segment bar (`activity_main.xml:26-34`, 12dp from
top) and the review bar (`view_review.xml:40-44`) lie under the clock; the record button
(`activity_main.xml:386-395`, 44dp from bottom) and the review save button (`view_review.xml:181-191`) sit close to the
gesture/3-button bar. API 30 and 34 are not affected (opaque black system bars).

**Files and lines:**

- `app/src/main/java/de/codinix/videoeditor/MainActivity.kt:276` (directly after `setContentView(binding.root)` in
  `onCreate`, `:273`): add one `ViewCompat.setOnApplyWindowInsetsListener(binding.root)` that reads
  `insets.getInsets(WindowInsetsCompat.Type.systemBars() or WindowInsetsCompat.Type.displayCutout())` and sets them as
  padding on `binding.root` (left, top, right, bottom), returning `WindowInsetsCompat.CONSUMED`. About 6 lines; the
  `<include android:id="@+id/review">` (`activity_main.xml:409`) is a child of the same root, so the review screen is
  covered too.
- `app/src/main/java/de/codinix/videoeditor/Sheet.kt:59-61` (conditional): bottom sheets are `BottomSheetDialog`
  windows. Only if the API 35 screenshot of a scrolled sheet (`02b-settings-scrolled`) shows the last row or the
  buttons under the navigation bar, add the bottom `systemBars()` inset as extra bottom padding on `root` (`:61`).
  If the screenshot is clean, `Sheet.kt` stays untouched (Material's dialog already handles it).
- No layout XML change, no theme change, no new strings. Libraries are present: `androidx.core:core-ktx:1.15.0`
  (`app/build.gradle.kts:89`).

**Approach:** inset padding on the root view, **without** calling `enableEdgeToEdge()`. Effect per API level:

- API 35/36: the root gets the status-bar/cutout height on top and the nav-bar height at the bottom; the black
  `windowBackground` (`themes.xml:5`) shows in those strips, so the app looks like it does on API 34 today (black
  status bar, light icons, controls below it).
- API 26–34: the window is not edge-to-edge, the decor view already consumes the system-bar insets, the listener
  receives zero insets and the padding is 0 – no visible change on older phones.

**Rejected alternative 1:** `<item name="android:windowOptOutEdgeToEdgeEnforcement">true</item>` in `themes.xml`.
The opt-out is deprecated and ignored for apps targeting SDK 36, so it would fix nothing on the owner's Android 16
phone.

**Rejected alternative 2 (for 1.1.6):** full-bleed camera with per-view margins plus a top scrim (concept item 1).
It changes the look on every API level and needs the A20 scrim, which is a design change waiting for the
`concept.approval`. The root-padding fix does not block it: when the concept is approved, the listener moves from the
root to the top/bottom control groups.

**Expected visible result:** on API 35/36 a black strip behind the status bar with readable white clock/icons; the
segment bar, review bar and back button start below it; record and save buttons end above the navigation bar. Camera
preview and player end at the strips (same as on API 34). API 30/34 screenshots are pixel-identical in layout to the
2026-11-13 run.

## A19 – fa/ar label and value run together in sheet rows

**Bug:** with `supportsRtl=false` the row layout stays left-to-right, but a Persian/Arabic label paragraph is RTL and
aligns to the **right** edge of its weighted box (`SheetRows.kt:51-55`). The value (`:83`) and the switch (`:63`, `:68`)
are added with no margin, so label and value touch: "فارسیزبان برنامه", "تشخیص خودکارزبان" (caption sheet),
"100 %شفافیت متن" (text sheet, slider row `:107-108`), and the switch-row label touches the switch.

**Files and lines (all `app/src/main/java/de/codinix/videoeditor/SheetRows.kt`):**

- `:53` label `TextView` and `:54` sub `TextView`: `textAlignment = View.TEXT_ALIGNMENT_VIEW_START`, so an RTL label
  sits at the left edge of its box like the English one (view direction stays LTR).
- `:83-85` `choice()`: add `value` with `LinearLayout.LayoutParams(WRAP_CONTENT, WRAP_CONTENT).apply { marginStart =
  (16 * dp).toInt() }`.
- `:62-64` and `:75` `switch()` (locked and normal): add the switch with `marginStart = 12dp` (locked row: on the
  crown icon, `:62`).
- `:107-108` `slider()`: add `valueText` with `marginStart = 16dp` (fixes the text-sheet case).
- `:97-99` `lockedRow()`: crown icon `marginStart = 12dp`.
- Values follow the concept's spacing (16 dp label–value, 12 dp text–switch); no new strings.

**Approach:** spacing and alignment inside the existing LTR rows; `supportsRtl=false` is kept (owner decision).

**Rejected alternative:** `android:supportsRtl="true"` in the manifest (or `layoutDirection = RTL` per row for fa/ar).
It mirrors the whole app or every sheet for two languages, conflicts with the owner's decision to stay LTR and
would need its own design check of every screen. The bug is only missing space.

**Expected visible result:** in fa and ar the label starts at the left edge of the card and the value or switch stays
at the right with at least 16 dp (12 dp to a switch) between them; en/de/fr/tr look unchanged except that a very long
label now wraps 16 dp earlier instead of touching the value.

## A22 – white segment bar invisible on bright footage

**Bug:** `SegmentProgressView.kt:20-21` paints the track in 33 % white (`0x55FFFFFF`) and recorded segments in pure
white. On a bright scene the whole bar disappears after recording; only the live green segment is visible
(`api35-en-07-segment-bar.png`, pixels at y 45 pure white).

**Files and lines (`app/src/main/java/de/codinix/videoeditor/SegmentProgressView.kt`):**

- `:20-21` add an `outlinePaint` (`Paint.Style.STROKE`, width 1dp from `resources.displayMetrics.density`, colour
  `0x8C000000` = 55 % black).
- `:60-61` after the track: draw the track outline (rect inset by half the stroke width).
- `:68-74` after each segment fill: draw the same outline around the segment rect.
- `:80-93` (review red overlay) unchanged; the outline from `:68-74` stays visible around it.
- Colours of track, segment, live, warning and armed states stay as they are.

**Approach:** a thin dark outline around track and segments, drawn with a stroke paint. It keeps the white/green/red
language of the bar and works on any footage (dark outline on bright, white fill on dark).

**Rejected alternative:** `Paint.setShadowLayer` for a soft shadow. Hardware-accelerated canvases support shadow
layers on shapes only from API 28; with `minSdk 26` the bar would need a software layer (`LAYER_TYPE_SOFTWARE`) for an
element that redraws every frame while recording. Also rejected for 1.1.6: the top scrim (A20), see A1.

**Note for the planner:** the outline is the smallest visible change that makes the element readable at all. If you
count it as visible design, move A22 into concept item 1 together with A20; PR-1 then contains A1 and A23 only.

**Expected visible result:** on the bright test scene the recorded segments show as white blocks with a dark edge;
on dark footage the bar looks as before (the dark edge is hardly visible on dark).

**Verification:** retake `api35-en-07-segment-bar.png` and `api35-en-06-recording.png` (API 35, en, bright synthetic
scene) and `api35-en-08-review.png` (red playback over outlined segments); plus `api36-en-08-review.png`. Language
does not matter for this view.

**JVM tests:** none – drawing code only.

## A23 – review shows position greater than total ("0:13 / 0:12")

**Bug:** `MainActivity.kt:2725` computes `pos = before + player.currentPosition`; the player can run a few hundred
ms past the summed `durationMs` at the end of the last segment. `fmt()` (`:3270-3273`) truncates to whole seconds, so
e.g. pos 13 100 ms and total 12 400 ms show "0:13 / 0:12" (`run1-api35-en-09-review-cut.png`).

**Files and lines:**

- New `app/src/main/java/de/codinix/videoeditor/ReviewTime.kt` (pure Kotlin, no Android imports):
  `object ReviewTime { fun clampPosition(posMs: Long, totalMs: Long): Long = posMs.coerceIn(0L, totalMs.coerceAtLeast(0L))`
  and `fun format(ms: Long, locale: Locale): String` (body moved from `fmt()`) `}`.
- `MainActivity.kt:2722-2737` (`updateReviewPosition`): add `val shown = ReviewTime.clampPosition(pos, total)` after
  `:2726`; use `shown` for `reviewStatus.text` (`:2736`) and `scrubBar.positionMs` (`:2732`, its own time labels in
  `ScrubBarView.kt:127-129` can show the same overrun). Keep the raw `pos` for `syncReviewOverlayAudio` (`:2727`),
  `captionView.setTime` (`:2733`) and `reviewBar.updatePlayback` (`:2728`, already clamped in its `onDraw`), so audio
  sync and captions are not shifted.
- `MainActivity.kt:3270-3273`: `fmt(ms)` becomes `ReviewTime.format(ms, Locale.getDefault())` – same output for all
  other callers (`:3115`, `:3173`, `:3247`, `:3249`).
- New test `app/src/test/java/de/codinix/videoeditor/ReviewTimeTest.kt`.

**Approach:** clamp the displayed position to `[0, total]` in a pure function; formatting unchanged.

**Rejected alternative:** round `fmt()` to the nearest second (or up). It does not remove the overrun (13 100 vs
12 400 rounds to "0:13 / 0:12" too) and it would change the recording timer and draft list times that use the same
function.

**Expected visible result:** at the end of playback and after scrubbing to the end the status reads "0:12 / 0:12";
position never exceeds the total.

**JVM unit tests (`ReviewTimeTest.kt`, run by `./gradlew testDebugUnitTest` in CI):**

- `clampPosition(13_100, 12_400) == 12_400` (the reported case);
- `clampPosition(-50, 12_400) == 0`; `clampPosition(5_000, 0) == 0`; `clampPosition(5_000, 12_400) == 5_000`;
- `format(12_999, Locale.US) == "0:12"`, `format(60_000, Locale.US) == "1:00"`, `format(0, Locale.US) == "0:00"`;
- the composed status string: `format(clampPosition(13_100, 12_400)) + " / " + format(12_400)` == `"0:12 / 0:12"`.
- fa/ar digit shaping and the bidi order of this string are A18, not part of 1.1.6.

**Verification:** retake `api35-en-09-review-cut.png` (API 35, en) after scrubbing to the end and pausing there;
`api35-de-09-review-cut.png` (de) as second language. The round-2 run caught the loop restart instead of the end
frame, so the script must pause playback before the shot.
